## 项目定位

**CodeRAG**（`D:\project\CodeRagAgent`）：面向大型 Java 代码库的 RAG 智能知识库。融合可切换双编码器语义向量（unified BGE-M3 / dual CodeBERT+BGE-M3）+ BM25 + 图遍历（PG `call_graph`）+ 三阶段精排，8 个 LangGraph Agent，支持增量更新与代码回滚。设计文档在仓库根 `*.md`。（GNN 图向量 / GraphRAG 社区摘要均**已弃用**。）

## 技术栈

- **后端**：FastAPI + Uvicorn + sse-starlette（SSE）+ LangGraph（Phase 7：主图地基 + Orchestrator **意图→Agent 分发表** + 代码理解/文档问答/变更影响/缺陷诊断/代码审查/测试生成 **6 个场景 Agent** 已落地（共享 `_base.run_scenario_agent` 骨架），`RAG_ENGINE` 开关，默认 legacy；code/doc/graph/bug/review/test 意图各走 `create_react_agent` 自动 Agent，余意图走 retrieve→generate。**Agent 步骤可观测性**：`agent_step` 工具轨迹持久化到 `retrieval_logs.agent_steps`，`GET /retrieval` 回放 `agent` 段。**Agent 面板**：`GET /v1/agents/{stats,runs}` 按需聚合 `retrieval_logs`（mode='agent' 成功信号 / agent_steps 轨迹 / user_feedback 满意度 / 降级率），前端 `/agents` 页 KPI+明细+流水；零新表）。包管理 uv。
- **前端**：React18 + TS + Vite + AntD5 + Zustand + React Router6。包管理 pnpm。
- **数据**：PostgreSQL 16（真相源）/ Milvus（向量）/ Elasticsearch（BM25）/ Redis 7 / MinIO。
- **模型**：嵌入**可切换双框架**——`EMBEDDING_STRATEGY=unified` 全 BGE-M3(1024d, API) / `=dual` 方案一：代码 CodeBERT(768d, 本地 `model_server`) + 文档 BGE-M3(1024d, API)，双路召回 + 统一 reranker 重排；LLM 走 API（DeepSeek）。默认 unified 不用 GPU；dual 代码侧需本地 model_server。

## 已确认决策

- **目标代码库**：通用可配置（`repo_path`），先用中小型 Java 仓库跑通；tree-sitter 先 Java。
- **向量库/图存储**：Milvus 全程（不用 Chroma）；图用 PG `call_graph` + DGL/PyG，不引入 Neo4j。
- **嵌入（2026-07-27 更新）**：**可切换双框架**——① `unified`：代码/文档统一 BGE-M3(1024d API)；② `dual`（[方案一](./嵌入向量方案.md)）：代码 CodeBERT(768d, 本地 `model_server` transformers) + 文档 BGE-M3(1024d API)，双 collection，双路召回由统一 reranker(Stage3) 重排。默认 unified。**图向量（Phase5 GNN / 路径 C）已弃用，保留图遍历（路径 D）。**
- **LLM**：DeepSeek API（httpx 流式）。
- **范围**：纵向 MVP 优先（Phase 0 + Phase 1 + 前端 P0 打通最短闭环），高级能力逐 Phase 加层。

## 关键坑（排错参考）

- **elasticsearch-py 9.x 与 ES 8.11 服务器不兼容**（Accept 版本报错）→ 锁 `elasticsearch>=8.11,<9`。
- **Milvus 必须配 `MINIO_ACCESS_KEY_ID/SECRET` 匹配 MinIO 的 `MINIO_ROOT_USER/PASSWORD`**，否则 crashloop（反复重启）。
- **`asyncio.to_thread` 传 keyword-only 参数（如 `top_k`）会 TypeError 且被 try/except 静默吞掉** → 把 `top_k` 改成位置参数（`es_client.search` / `milvus_client.search`）。
- **硅基流动 `/rerank` 无 `bge-reranker-base`**（HTTP 400 Model does not exist），只有 `BAAI/bge-reranker-v2-m3` → 粗排模型（`RERANKER_COARSE_MODEL`）留空走单阶段精排；精排每阶段须独立 try/except，否则粗排失败会连带把精排也吞掉（曾导致 `rerank_on=false` 静默失效）。
- **中文 Windows GBK**：`alembic.ini` 纯英文注释；脚本输出 emoji/中文需 `sys.stdout.reconfigure(encoding="utf-8")`。
- **pytest 收集碰撞**：`app/` 下有以 `test_` 开头的业务模块（如「测试生成 Agent」的 `agents/test_generation.py`，其节点函数 `test_generation` 也以 `test_` 开头），无 `testpaths` 时 `pytest` 会把它当测试收集（`fixture 'state' not found`）。两处互补修复：测试文件用模块属性 `tg.test_generation` 而非直接 `from ... import test_generation`（避免裸名进测试命名空间）；`pyproject.toml` 设 `testpaths=["tests"]`（无参 `pytest` 不再扫 `app/`）。
- **国内 Docker**：`daemon.json` 配可用镜像源（1ms.run / xuanyuan.me / daocloud / 1panel / nju / rat.dev；旧的 aliyun/163/tencent 已失效）；etcd 用 docker.io 的 `bitnami/etcd`（原 `quay.io` 不走加速）；Git Bash 调 docker 需把 `C:\Program Files\Docker\Docker\resources\bin` 加入 PATH（否则 `docker-credential-desktop` 找不到）。
- **前端容器构建**：`pnpm-workspace.yaml`（`allowBuilds: esbuild: true`）必须 COPY 进镜像，否则 pnpm 11 把 ignored builds 当错误致构建失败。
