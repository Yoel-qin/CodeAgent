### Q1. 目标代码库与语言是什么？

**背景**：设计文档以 **Apache RocketMQ（Java）** 为蓝本举例，但项目目录是 `CodeRagAgent`。系统是只服务 RocketMQ，还是通用的、可指向任意仓库？

- tree-sitter 解析目前只设计了 Java（`tree-sitter-java`）。若实际代码库含其他语言（Go/Python/TS…），需扩展语法。
- 评测集、模块划分（broker/client/namesrv/store…）高度依赖具体仓库。

**我的默认裁决（D8）**：系统与具体仓库解耦，`repo_path` 配置化；先用**一个中小型开源 Java 仓库**（或 RocketMQ 子模块）跑通全链路。tree-sitter 先实现 Java，架构上预留多语言扩展点。

**请确认**：
- [ ] 目标仓库是 RocketMQ 全量 / RocketMQ 子模块 / 你自己的私有仓库 / 其他开源仓库？

- [ ] 仓库如何提供给容器（本地挂载路径 / 容器内 git clone / 提供镜像地址）？

### Q2. 向量库与图存储到底用哪套？（文档存在冲突）

**背景**：三份文档对存储层说法不一致：

| 文档 | 向量库 | 图存储 |
| --- | --- | --- |
| `技术栈架构设计.md` | **Chroma** | **Neo4j 5** |
| `coderag后端设计方案.md` | **Milvus**（含 graph_embedding 多向量字段、HNSW） | PG `call_graph` + **DGL/PyG GNN**（Neo4j 仅 `graph_traverse` 可选） |
| `mcp工具集合.md` | "Chroma/Milvus"（两者都写） | `neo4j_query` + `graph_traverse`（PG 递归 CTE） |
| `api接口清单.md`（监控） | `milvus_gb` / `milvus.total_vectors` | `gnn.total_nodes` |

关键分歧：
- **Chroma 不支持单 collection 多向量字段**，而设计强烈依赖 `graph_embedding` 与语义向量同库检索（Phase 5 图向量路径）。若用 Chroma，要么放弃图向量同库检索，要么另起一个 collection 做近似。
- **Neo4j 是否必须**：后端设计的"真相源"是 PG（调用边、关联、变更历史全在 PG），Neo4j 在 `mcp工具集合` 里只是可选的 `neo4j_query` 工具。

**我的默认裁决（D1/D2）**：
- 向量库：**Milvus**（与后端设计、API 监控指标一致，支持多向量字段）。若硬件/资源吃紧，**Phase 1 MVP 用 Chroma** 跑通单向量，Phase 5 前切到 Milvus。
- 图存储：**PG `call_graph` + 递归 CTE 做 BFS**，GNN 用 **DGL/PyG**；**Neo4j 不引入**（除非需要交互式 Cypher 探索，可作为可选容器后加）。

**请确认**：
- [ ] 向量库：Milvus（推荐）/ Chroma（轻量）/ 其他？
- [ ] Neo4j：不引入（推荐）/ 引入作为可视化探索组件？
- [ ] 是否接受"Phase 1 用 Chroma、Phase 5 前切 Milvus"的渐进策略？

### Q3. 本机是否有可用的 NVIDIA GPU？Windows Docker GPU 透传可用吗？

**背景**：`后端设计方案 §19` 假设 **RTX 4050 8GB 本地 GPU**，5 个模型（CodeBERT/BGE-M3/R-GCN/bge-reranker-base/v2-m3）本地 FP16 共占 ~3.7GB。你要求"**基础设施全部跑在 Docker 上**"。

**风险**：Windows 上 Docker Desktop 用 WSL2 后端，GPU 透传需要：
- Windows 11 + WSL2 + NVIDIA Windows 驱动（含 WSL 组件）；
- `nvidia-container-toolkit` 在 WSL 内安装；
- 容器内 CUDA 可见。
这套链路在 Windows 上**可行但脆弱**（驱动版本、WSL 内核、Docker Desktop 版本都可能踩坑）。

**我的默认裁决（D9）**：
- 默认按 §19 假设有本地 GPU，`model_server` 容器走 GPU profile；
- 同时**内置 CPU/API 回退开关**：若无 GPU，嵌入/重排临时走兼容 API（如硅基流动/OpenAI 兼容的 embedding 与 rerank 端点），GNN 走 CPU 或用 Node2Vec 占位。
- 设计统一通过 `model_server` 抽象，上层无感。

**请确认**：
- [ ] 本机显卡型号 / 显存？（是否就是 RTX 4050 8GB？）
- [ ] 是否已在 WSL2 成功跑过 Docker + CUDA？还是需要我把"模型走 API、Docker 只跑 CPU 服务"作为默认？
- [ ] 若走 API 方案，DeepSeek/阿里云百炼/硅基流动 的 API Key 是否已就绪？
